# RESILIENT-AMR: A* 주행과 환경 변화 기억

검증된 장애물 변화를 별도 지도에 저장하고, 다음 경로 계획에 재사용하는 TurtleBot3/ROS 2 개인 프로젝트 초안입니다.

## 목표

1. 기본 지도는 보존하고, 새 장애물 관측을 변화 후보로 관리합니다.
2. 반복 관측으로 확인된 변화만 별도 환경 기억 파일에 저장합니다.
3. 장애물이 사라진 뒤 충분히 관측되면 기억에서 제거합니다.
4. A*가 기본 지도와 확인된 장애물 기억을 함께 사용해 경로를 계획합니다.
5. 저장 후 다시 불러와도 같은 장애물 정보를 경로 계획에 반영합니다.

여기서 “학습”은 신경망 학습이 아니라, 관측 이력을 누적해 환경 변화를 검증하고 재사용하는 지속 메모리를 뜻합니다.

## 현재 단계

현재 구현은 ROS 2나 Gazebo에 연결하기 전, 격자 지도에서 알고리즘과 저장/복구 흐름을 확인하는 Python 프로토타입입니다. LiDAR/TF2 연결, Nav2 연동, 실제 TurtleBot3 주행은 학원 PC 환경에서 다음 단계로 붙입니다.

## 실행

Python 3.10 이상, 외부 패키지 없이 실행할 수 있습니다.

```bash
python3 -m src.resilient_amr.demo
```

기억 파일은 기본으로 `artifacts/environment_memory.json`에 생성됩니다. 저장 파일은 재현을 위해 Git에 커밋하지 않습니다.

## 시험

```bash
python3 -m unittest discover -s tests -v
```

시험은 A*의 장애물 회피, 대각선 코너 통과 방지, 장애물 변화의 확정/해제, 저장 후 복구를 확인합니다.

## ROS 2 연결 구상

- 입력: `/map` (`nav_msgs/msg/OccupancyGrid`), `/scan` (`sensor_msgs/msg/LaserScan`), TF2
- 주행 요청: Nav2 `NavigateToPose` 액션
- 출력: 확인된 변화 오버레이를 별도 지도 파일과 `OccupancyGrid`로 제공
- 기준: `map` 좌표계, 거리 m, 각도 rad
- A* 격자 엔진은 ROS 메시지와 분리해 유지하고, ROS 어댑터가 지도/센서 입출력을 변환합니다.

Nav2와의 변화 지도 반영 방식은 Keepout Filter 또는 별도 costmap layer를 비교해 학원 PC의 ROS 2 배포판에서 검증한 뒤 선택합니다. 기본 지도는 덮어쓰지 않습니다.

## 저장 데이터

`environment_memory.json`에는 격자 크기와 셀별 상태(`candidate`, `confirmed`), 점유 관측 수, 비어 있음 관측 수가 저장됩니다. 현재 격자 프로토타입은 ROS 지도 해상도와 원점 변환을 다루지 않습니다. ROS 어댑터 단계에서 해상도·원점·좌표계 메타데이터도 저장하고, 현재 지도와 일치하는지 검사해야 합니다.

## 다음 단계

1. 학원 PC에서 저장된 ROS 2 배포판, TurtleBot3 모델, Nav2 설정을 확인합니다.
2. Gazebo에서 `/map`, `/scan`, TF 트리와 Nav2 액션을 확인합니다.
3. ROS 어댑터가 변화 오버레이를 Nav2 전역 경로 계획에 반영하도록 연결합니다.
4. 장애물 추가 → 반복 관측 → 저장 → 재시작 → 재사용 → 제거 관측 → 기억 갱신 시나리오를 시연합니다.

## 범위 밖

초기 버전은 YOLO, 데이터베이스, 웹 대시보드, 실제 로봇 안전 인증을 포함하지 않습니다. 격자 데모만으로 실물 주행 안전성이 보장되지는 않습니다.
